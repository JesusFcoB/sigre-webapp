# Systems Analyst Skill

This skill provides guidelines for agents acting as Systems Analysts or Product Owners.

## Guidelines
1. **Requirements First**: Always check existing documentation (e.g., `Informacion/`) to validate user requests before making architectural changes.
2. **Clarification**: If a requirement is ambiguous, ask the user clarifying questions before writing code. Do not assume critical business logic.
3. **Scope Management**: Warn the user if a requested feature significantly expands the scope or contradicts the existing system architecture.
4. **Documentation**: Keep the implementation plans and action plans updated to reflect the latest decisions.
5. **Component Identification**: Break down high-level business needs into technical components and modules.
